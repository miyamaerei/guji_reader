## A. 前端 Bug（必修）

### A1. 「整页」按钮全部失效——双 `#` 路由
- 位置：`src/components/reader/DetailPanel.vue:56`
- 写法：`:href="`#${routeOf}`"`，而 `routeOf`（`core/routes.ts:14` 的 `detailHref`）返回值已含 `#/detail/...`，拼接后变成 `#/#/detail/sdr/item/01-003`。
- 现象：hash 路由无法匹配 → 命中 catch-all 强制跳回书架。条目详情/实体详情/层记录的「整页」入口全中招。
- 验证：直接访问正确的 `#/detail/sdr/item/01-003` 页面正常，证明只是链接拼错。
- 修复：模板改为 `:href="routeOf"`。

### A2. 书与书之间跳转后，阅读器「0 卷 0 条」空白
- 位置：`src/views/ReaderView.vue:212-218` 的 `watch(bookId)`
- 根因：watcher 只重置 `loadedVols/chunkMap` 并 `ensureBook()`，**没有重新加载首卷**；`loadVolume(首卷)` 只写在 `onMounted` 里，而同路由参数变化时组件不重新 mount。
- 复现：`/#/reader/wzz` →（SPA 内改 hash）→ `/#/reader/sdr` → 显示「已加载 0/38 卷 · 0 条」「尚未加载任何条目」，正文空白。整页刷新同一 URL 则正常自动加载第 01 卷。书架卡片点进去正常（走了 `setBook` 预加载路径）。
- 修复：watch(bookId) 里 ensureBook 后补 `loadVolume(volumes[0]) + toc.openOnly(...)`，或把 onMounted 的首卷逻辑抽成函数两处调用。

### A3. 每次进阅读器必发 `/api/books//join` 404 + Vue mounted 报错
- 位置：`src/components/reader/TocPanel.vue:29-33`
- 根因：子组件 `onMounted` 先于父级 ReaderView 的 `onMounted` 执行，此时 `book.currentBookId` 还是 `''`，`layers.join('')` 请求空 bookId。联邦服务对空段返回错误（vite 代理下 404；直连 8787 时回 200 的 index.html，两种情况都让 `jf.rows` 挂掉）。
- 现象：控制台每次都有 `[Vue warn]: Unhandled error during execution of mounted hook at <TocPanel chapters=[]>`；网络里固定多一条 404。
- 修复：`layers.join(book.currentBookId || props 里透传的 bookId)`，或等 `built/book.config` 就绪后再加载。

### A4. 联邦模式下 ent-ref 字段渲染成 `[object Object]`
- 位置：`src/core/format.ts:36-45`（`displayValue` 只处理数组，单对象走 `String(v)`）
- 根因：联邦库 payload 里 `person/office/institution` 等 ent-ref 是对象（`{"text":"顺天府","ent_ids":[]}`），不是字符串。JSON 包模式这些字段是纯字符串所以没暴露。
- 现象：总览页「职官任职」表、条目详情的字段表里，「机构/官职/人物」三列全是 `[object Object]`（截图 list-view.png 可对照）。
- 修复：`displayValue` 对非数组对象走 `labelOf()`。

### A5. 条目详情看不到书证/原文（联邦模式）
- 位置：`src/components/reader/ItemDetail.vue:70` → `layers.load(bookId, layer)` 未传 opts
- 根因：`deriveLayer`（server/fed-lib.mjs:560）在无 `itemId` 且无 `full=1` 时把 `original` 清空。JSON 包模式 layer 文件自带 original 所以正常。
- 现象：详情里「原文 —」「书证（无）」，而接口其实有 `evidence/original` 全文。
- 修复：ItemDetail 调 `layers.load(bookId, layer, { itemId, full: true })`（dataProvider.layer 已支持，见 api.ts:140）。

### A6. 联邦模式实体不按类型着色
- 位置：`server/fed-lib.mjs:363` `deriveConfig` 只产 `colors: { primary }`
- 根因：JSON 包 `book.config.json` 有 `entityTypes` 8 色映射（person/place/official/work/institution/era/posthumous/unknown），联邦推导的 config 没有，前端 `colors.entityTypes ?? {}` 退化为空 → 全部实体 span 同一个颜色（实测 155 个 span 全为 rgb(24,95,165)）。
- 现象：正文里机构/人物/地点无法按类型区分颜色（title tooltip 有类型，仅颜色丢失）。
- 修复：deriveConfig 按库内 nodes.type 值域补一组默认配色。

## B. 服务端 Bug（必修）

### B1. event 层全线 404——`rawLayerKey` 别名映射方向错误
- 位置：`server/fed-lib.mjs:206-208`（`LAYER_KEY_ALIAS = { evt: 'event' }` 的反查）
- 根因：`rawLayerKey('event')` 恒等于 `'evt'`，但库里 **sdr/kzz/qb/wzz/xgf/xyf 的层键就是 `event`**（只有 xzl/ysz 用 `evt`）。`deriveLayer` 用错误的键查 records → 0 条。
- 现象：
  - `GET /api/books/sdr/layers/event` → `{"error":"书 sdr 无层 event"}`（404）
  - 阅读器条目详情展开「事件」层：空白，无任何记录也无提示
  - 总览页「事件」tab：「层数据缺失，点此重试」，共 0 条（实际 234 条）
- 口径割裂：`deriveJoin` 按原键计数（所以目录徽标/统计有事件数），`deriveLayer`/`deriveEnums` 用别转后的键（查不到）。
- 修复：deriveLayer/deriveEnums 里 `layer_key IN (?, ?)` 同时匹配原名与别名（参考 /api/books 的 `IN ('event','evt')` 写法）。

### B2. 书架「实体」数不去重，恒等于「标注」数
- 位置：`server/sqlite-api.mjs:127-133`（`entities: nodes.c`，注释写「nodes 去重」但 SQL 是 `COUNT(*)`）
- 实测（COUNT(DISTINCT normalized)）：
  | 书 | 书架显示实体(=标注) | 实际去重实体 |
  |---|---|---|
  | 水东日记 | 2253 | **1900**（与 JSON 包一致） |
  | 客座赘语 | 8481 | 6175 |
  | 五杂俎 | 5821 | 3832 |
  | 蘧编 | 997 | 805 |
- 现象：所有书卡片上「实体 N / 标注 N」数值相同，失去统计意义。
- 修复：`COUNT(DISTINCT json_extract(payload,'$.normalized'))`。

## E. 第二轮走查：风俗层显示问题（2026-10-13 当晚续，用户报「风俗这里显示有问题」）

环境同上。症状两则：kzz 总览页「风俗」(cus) 层 ① 字段标签英文原文（layer/cus_id/description）；
② 长 description 横向溢出卡片面板（用户截图墨迹分析：首卡描述延伸至 x=1876 全宽，其余卡被挤在
326px 窄列，面板 3/4 空白）。顺带查出并修复 P5.2 虚拟滚动改造引入的布局回归。

### E1. 层字段标签英文原文
- 位置：`server/fed-lib.mjs` `FIELD_LABELS`
- 根因：联邦 `records.payload` 字段名是英文 snake_case；`fieldLabel()` 字典只覆盖少量键，
  `description/region/cus_id/_layer` 等无条目 → 卡片与详情直接吐英文。
- 修复：`FIELD_LABELS` 补 **118 条**汉化（全部对照库内实际值核过语义，如 `description:'描述'`、
  `region:'地域'`、`term:'词条'`、`keeper:'经管人'`、`modals:'模态词'`）；`fieldLabel()` 加重写通用回退：
  `*_ent_ids` → 「…实体」，`*_id` → 「…主键」（词干有汉化时才拼，否则原样返回）。
- 验证：cus 卡片标签 = 描述/地域/词条/类型/卷，全中文。

### E2. 长 description 横向溢出卡片
- 位置：`ListView.vue` / `LayerRecordDetail.vue` / `StructTabs.vue` / `EntityDetail.vue` /
  `ItemDetail.vue` / `TrlParallel.vue`
- 根因：CSS 网格 `1fr` = `minmax(auto, 1fr)`，其最小值是 **min-content**——中文长串（无空格换行点）
  把网格列撑爆，整条网格溢出容器（首卡描述实测延伸至 x=1876，超出视口）。
- 修复：全链路列轨 `1fr` → `minmax(0, 1fr)`；`dd`/标题加 `min-width:0` +
  `overflow-wrap:anywhere; word-break:break-word` 双保险。
- 验证：浏览器实测 `scrollWidth == clientWidth == 1249`，卡片 1160px 适配 1209px 面板，
  首卡描述（约 150 字）在卡内完整换行。

### E3. P5.2 虚拟滚动引入的卡片流窄列回归
- 位置：`ListView.vue` `.cards.vcards`
- 根因：VirtualList 的绝对定位行由外壳 `.vlist-wrap` 承载，而外壳是 `.cards`（auto-fill 多列网格）的
  **单个网格项** → 卡片流被挤进最左一列，右侧 3/4 面板空白。
- 修复：`.cards.vcards{display:block}`（卡片视图不做多列网格，由虚拟滚动自己排）。
- 验证：卡片通栏铺满面板（E2 同次实测）。

### E4. 卡片列表残留恒空的 `original` 行 + 字段噪音治理（数据驱动派生）
- 位置：`server/fed-lib.mjs` `deriveConfig` 统计块
- 根因：瘦身契约（`src/stores/layers.ts` `load()` 对非 ent 层 full 默认 false，列表记录不带 original）
  下，`original` 行恒显示「—」；原 `avgLen > 300` 隐藏规则漏掉短原文层（ppy/opn avg=297 实测残留）。
  同类噪音：`norm` 在库内实为 original 副本（avg 300–1100，distinct 与 original 相同，C 类已坐实）、
  `_layer/cus_id/item_id` 系统字段。
- 修复（全部数据驱动，零硬编码）：
  - `key === 'original'` 无条件 `hideInList`（原文由 EvidenceBlock 在详情 `full=1` 时提供，不丢信息；
    ent/geo 层 `original` 是带 start/end 的 mention surface，不走此规则）；
  - 统计规则：系统字段（`_` 前缀 / `*_id`）/ distinct≤1 常量字段 / avg>300 长文字段 → `hideInList`；
  - `maxLen>120 且 withNl>0` → `view:'block'` 详情块状渲染；
  - 新增 `TITLE_PREFERENCE` + `titleKey`（term/name/person/office/action… + avg≤30/max≤200 短字段校验），
    卡片标题不再退回记录 id。
- 验证：kzz 10 个卡片层 titleKey 全部合理（appt=person、cit=cited_work、event=action、lit=title、
  obj/nam=name、rel=person_a、ming/opn=who、cus=term、trl 无候选回落首字段）；`npm test` 67 项通过、
  `npm run typecheck` 通过；浏览器复核 cus 卡片无 original/norm/系统字段行。

## G. 第三轮走查：古风改造引入/暴露的故障（2026-10-13 深夜）

### G1. 阅读器整页空白：`LayerRecordDetail.vue` 残留重复 `</style>`（根因：Vite transform 500）
- 症状：`#/reader/kzz` 的 `.app-main` 渲染为 `<!---->`，书架正常；页内跳转视图不切换、
  window error/unhandledrejection 全空。
- 定位法（可复用）：**全量 transform 探活**——对 `src/` 每个文件 curl dev server，
  非 200 即坏：
  ```bash
  for f in $(find src -type f); do curl -s --noproxy '*' -o /dev/null -w "%{http_code}\n" \
    "http://127.0.0.1:5173/$f"; done
  ```
- 真因：DetailPanel 静态依赖 LayerRecordDetail，该文件尾部两个 `</style>`
  （Invalid end tag）→ ReaderView 懒加载链断裂 → vue-router 静默中止导航（URL 变、视图不动），
  直接加载时 RouterView 保持空注释。**教训：路由级懒加载失败是无console噪音的，
  transform 探活比 window.onerror 钩子有效得多。**
- 修复：删重复闭合标签。已全站复查无同类残留。

### G2. 外壳 `min-height:100vh` 被内容撑爆，卷轴纸身「内部滚动」名存实亡
- 症状：阅读器 `docH=19035 vs winH=569`——`.stream` 元素被拉到 18909px（等于内容高），
  overflow-y:auto 形同虚设，实际整页文档滚动；ItemStream 的 scroll 监听/IntersectionObserver/
  currentIid 全部失效（focus 高亮、触底续接逻辑死亡）。
- 根因：`html/body/#app/.app-shell` 全部只有 `min-height`——flex 内容定容（§9.7）把外壳撑到
  内容高，`.reader{height:100%}` 再顺着放大。旧版同款外壳为何没爆：grid 直接子项
  `.stream` 能吃到行拉伸，包了 `.col-body` 后链条感知变化——**靠推理不如靠测量**，
  曾用 `git checkout HEAD -- src/` 对照旧版，反而踩到 G6 的坑（见下）。
- 修复（styles.css + ReaderView.vue）：定高链 `html,body,#app{height:100%}`、
  `.app-shell{height:100%;overflow:hidden}`、`.reader` 由 `height:100%` 改
  `flex:1;min-height:0`（不定高父级上 height:100% 会退化成 auto）。四张 `.page` 页
  （书架/总览/检索/详情）原本就带 `overflow:auto`，改为栏内滚、题头常驻，行为更一致。
- 验证：docH=569=winH；stream 446px 内滚 18909px 内容；滚到底 34→70 卡；
  书架/总览/检索/详情页 docH 全部锁 569 且各自内部可滚。
